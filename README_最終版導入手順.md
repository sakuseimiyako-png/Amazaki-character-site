# 『物語之終幕』管理画面 v1.4 — 導入・動作確認手順

> **現在公開中の本番(main)は触らず、`feature/supabase-admin-v13` ブランチでテストする。** v1.4は、v1.3への機能追加です。キャラクタープロフィールの原文・立ち絵・切替機能は変更しません。
>
> **大事：ZIP内の `supabase-config.js` はサンプル（未設定）です。** v1.3で既に記入した設定ファイルを維持してください。推奨は「差分更新用ZIP」の5ファイルだけをGitHubにアップロードすることです。

## 0. 現在のバックアップ

- GitHub の **main → Code → Download ZIP** で正常動作中の公開サイトを保存。
- `feature/supabase-admin-v13` の **Code → Download ZIP** で今動いている管理画面も別途保存。
- 管理画面 `/admin.html` でログインし、**DB記事をJSON保存**。記事の実データがまだ0件でも保存しておく。
- Supabase Storage `entry-images` の画像ファイル実体も必要に応じて個別にダウンロード。
- ZIPとJSONを、PCの別フォルダまたは安全な別保存先に複製。パスワードや `sb_secret_...` はこれらに含めない。

## 1. 先にSupabaseにSQLを実行する（必須）

1. `SQL_FIRST_RUN_v1_4.sql` をメモ帳で開き、内容をコピー。SQLファイルは消さずに保管。
2. Supabase → 対象 `Amasaki-character-site` → **SQL Editor → New query**。
3. コードをすべて貼り付けて **Run**。`JWT failed verification` が出たら再ログインし、作業を止めて確認する。更新前に必ずコードをファイル保存。
4. 実行結果の最後に `site_entries_category_check` と `site_section_state` が表示されることを確認。
5. このSQLは既存の `site_entries` の行、`site_admins` の3アカウント、Storageのバケット、プロフィールを削除しない。

**SQLが成功するまでv1.4のGitHubアップロードをしない。** 先にアップロードすると追加分類の保存・読み込みがエラーになる。

## 2. 差分更新ZIPで、テストブランチの5ファイルだけを更新

1. `AMASAKI_v1_4_PATCH.zip` を「すべて展開」。
2. GitHubの `sakuseimiyako-png/Amazaki-character-site` を開き、**左上のブランチが `feature/supabase-admin-v13`** であることを確認。
3. Add file → Upload files。展開したフォルダ内の **以下の5ファイルのみ** をアップロード：`admin.html`、`admin.css`、`admin.js`、`app.js`、`styles.css`。
4. Commit changes（例：`Add full archive editor and real-page preview v1.4`）。**mainへ直接コミットしない／Mergeしない。**
5. `supabase-config.js` は **上書きしない**。現在動作しているv1.3のProject URLとPublishable keyをそのまま使う。**Secret key / service_role / パスワードを追加しない。**

## 3. Vercel Previewでテスト

1. Vercel → `amasaki-character-site` → Deployments → `feature/supabase-admin-v13` の最新 Preview が `Ready` か確認。
2. Preview URL末尾に `/admin.html` をつけてアクセス。登録済みの管理者アカウントでログイン。
3. 管理画面左の分類選択に **異能道具 / 能力 / 使用技 / 世界観 / 関係 / 都での歴史** の6分類が表示されるか確認。
4. 既存記事を編集する前に、画面の下の **「未登録の分類に元サイトの記事を取り込み」** ボタンを一度押す。これは取り込まれていない分類のみを移行し、すでにDBにある記事は上書きしない。いったん取り込むと元サイトの静的データの一部がDB管理に切り替わる。
5. **世界観** を選んで1記事を選択→タイトル・本文を試しに変更。**「公開ページでプレビュー（保存しない）」** をクリック。公開サイトのWORLD ARCHIVEと同じページ表示で確認できる。**この操作ではDBは変更されない。**
6. プレビュー内に **PC / スマホ** の幅切替がある。ページの見え方を確認して閉じる。
7. **世界観 / 関係 / 都での歴史** のそれぞれで新規記事→プレビュー→下書き保存→公開変更→一般閲覧側を確認。テスト投稿には`【テスト】`と付けて、必要なら削除。世界観・関係・歴史の画像は16:9、異能道具・能力・使用技は5:4。
8. **閲覧側** はログイン不要で確認。公開済み記事はページを再読み込みすると反映。下書きは表示されない。
9. 新規記事の削除をテストした場合、最後の記事を消しても古い静的記事が勝手に復活しないことを確認。
10. 通常／覚醒の立ち絵およびキャラクタープロフィールを確認。**この部分は元のまま**。

**注意：テストブランチでも保存した記事は実際のSupabaseプロジェクトに書き込まれるため、同じデータベースを使う公開版が存在する場合、公開設定の変更は影響し得ます。** 初回はプレビューだけで確認し、保存試験は下書きで行い、公開テストの直前にJSONを取ってください。完全分離するには独立したテスト用Supabaseプロジェクトが必要です。

## 4. 管理画面の機能

- 6分類の **新規追加・編集・削除・並べ替え・公開/下書き**。
- 3分類（異能道具・能力・使用技）の **通常/覚醒** を別データで管理。
- 装飾本文（太字、斜体、下線、見出し、文字サイズ、色、区切り、箇条書き）と表示演出。
- 各記事の画像アップロード・トリミング・解除。画像サイズは保存時WebPへ変換。
- 本番サイトと同じ描画処理を使った**保存前プレビュー**（PC・スマホ表示切替）。
- JSONバックアップ／コピー／IDベースの復元（更新・追加）。v1.4ではDBの公開区画切替状態もJSONに含む。
- 既存PROFILEの変更はしない（最終要望を尊重）。

## 5. バックアップと復元の限界

- 「DB記事をJSON保存」は、記事本文、タイトル、画像パス、並び順、公開状態、区画の切り替え状態を保存できる。
- **画像・動画のバイナリ実体はJSONに含まれない。** 必ず`entry-images`とGitHubの`assets`を別に保存する。削除前のJSONダウンロードは自動だが、画像の一括ZIP自動保存と一括画像復元はこのv1.4では未実装。
- 復元は同一IDの記事を上書き、ないIDを追加する。バックアップにない記事を全削除する「完全同期」ではない。
- GitHubの正常なmain版のZIP・Supabase記事JSON・Storage画像という**3点セット**を保存する。
- 更新後に問題があればテストブランチのコミットを元に戻す。本番mainを変更していなければ本番コードは維持される。

## 6. 本番公開

世界観・関係・歴史のCRUD、プレビュー、既存能力・異能道具・技、画像、プロフィール、PC/スマホ、匿名閲覧、権限、バックアップの確認後にのみ、GitHubのテストブランチからmainへプルリクエストをマージ。Vercelがmain更新を検知し本番配信する。

## 7. 見落とし注意

- バケット`entry-images`のAllowed MIME Typesが`Any`なら、Storageの設定で `image/png` / `image/jpeg` / `image/webp` に絞るのが推奨。
- 認証URL `/admin.html` は他人もアクセス可能だが、パスワードなしでは編集できず、サーバー側のRLSで書き込みを制限する。未確認のアカウントでの権限チェックも実施する。
- 世界観などの静的データが未取り込みの状態では、新規公開により元記事が隠れる事故を防ぐため、まず初期取り込みを要求する。
- Google Fontsが読み込めない環境でも代替フォントで表示する。
